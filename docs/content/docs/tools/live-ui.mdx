---
title: Live UI
description: A local editor and preview that re-renders on save.
---

`spinagram serve` opens a local web UI with live reload: the diagram, its Python and CSS side by side, editable
in the browser. It needs the `ui` extra
(`pip install 'spinagram[ui]'`); the web bundle ships in the wheel, no Node needed.

```bash
spinagram serve specs/ --theme ../my-theme          # http://127.0.0.1:8765, opens the browser
spinagram serve specs/ --layout elk --port 0 --no-open
```

A folder is scanned with its subfolders, so `spinagram serve examples/` shows every example; hidden folders and
`node_modules`, `__pycache__`, `.venv`, `venv`, `out`, `dist`, `build` and `site-packages` are skipped, and at
most 2,000 specs load at once.

## Edit the code next to the diagram

Open a diagram and press **Code** (or `e`). The panel shows the diagram's spec file first, then every stylesheet
file of its cascade (folder `_defaults.yaml` sheets, then the diagram's own), with Python, CSS and YAML
highlighting.

1. Edit a tab: a dot marks it as modified.
2. Press **Cmd+S** / **Ctrl+S** or **Save**. The file is written and the diagram re-renders, usually in well
   under a second.
3. If the spec no longer loads, your text stays in the editor and the diagram shows the error (file and line)
   over the last good render. Fix and save again.

**Find a box in the code.** With the panel open, click a box in the diagram: the spec tab scrolls to the first
line that has its title as a string, such as `d.box("Karpenter", ...)`.

**Changes from elsewhere.** Saving in your own editor updates a clean tab in place. If a tab has unsaved edits
when the file changes on disk, or a save finds the file changed since it was read, the panel keeps your text
and asks: **Reload from disk** or **Keep mine** (then save to overwrite). Leaving the diagram or closing the
page with unsaved edits asks for confirmation.

## Edit on the canvas

Press **Canvas** (or `c`) on a diagram that is a hand-placed YAML spec: one diagram per file, with coordinates
(`x`/`y` or `at:`) and no `layout:` engine. Rows and columns are fine. Python specs, engine layouts and snakes keep
the read-only view, and the page says so. An edit updates the picture in place: icons and the toolbar are never torn down and redrawn, only the items that changed. Every canvas edit is a minimal patch of the YAML file, written through the
same version-checked save as the code panel, so comments, key order and untouched entries stay as they were. Try
it on `examples/showcase/editable_platform.yaml`.

| Do this | Result |
|---|---|
| Toolbar on the left edge of the canvas | Icon buttons for the tools and actions below; hover one for its name and key. The dock button at its end moves it to the bottom of the canvas (above the zoom controls) and back; the choice is remembered in the browser |
| `V` Select, `H` Pan | Select is the default. Pan drags the view; holding Space pans in any tool |
| `B` Box, `T` Text, `Z` Zone | A click places the default size centred on the point; a drag draws the rectangle (snapped to the grid). Text opens the title editor at once. The tool returns to Select after one use; hold Shift to keep it |
| `C` Connect | Drag from one node to another to add an edge (`from -> to`; parallel edges are fine). Releasing on empty canvas, the same node or a zone adds nothing. With the canvas off, `c` still turns it on |
| Click a node, zone header or row/column | Selects it; with the code panel open, its YAML entry is highlighted |
| Shift+click, or drag on empty canvas | Adds to the selection, or draws a selection box (Alt+drag pans) |
| Drag | Moves the selection, snapped to a 10 px grid; edges follow while you drag |
| Drag onto a zone, or out of one | Puts the node or zone in the zone under its centre, or takes it out |
| Drag a zone by its header | Moves the zone and everything inside it |
| Ctrl/Cmd+G, **Group as row**, **Group as column** | Groups the selected nodes into a row or column (gap 20) |
| Drop a node on a row or column, drag a member out | Inserts it at the gap its centre falls in, or removes it |
| Select a row or column | **Ungroup**, and its **Gap** (and **Align**, for containers inside a zone) |
| Select one zone | The bar gets a **style** picker: every provider zone style with its icon, and **Generic zone** |
| Click an edge (its line or its label) | Selects the arrow: it is highlighted with a handle at each end. Shift+click adds more; **Delete** removes it; double-click edits its label |
| Drag an end handle of a selected edge | Reconnects that end to the node you release on; a release on empty canvas, a zone, or the edge's own other end changes nothing |
| Double-click | Renames a node or a zone label, or edits an edge label |
| `/` or Ctrl/Cmd+K | Opens the palette (it starts collapsed, next to the diagram, and remembers its state) and focuses the search; arrows move, Enter adds at the centre of the canvas; Esc closes it |
| Drag a palette item onto the canvas | Adds an icon node (`220 × 96`, centred on the drop point), a shape, or a zone |
| Ctrl/Cmd+Z, Shift+Ctrl/Cmd+Z | Undoes and redoes the last 50 canvas edits of this page |
| Delete / Backspace | Removes the selection with the edges that touch it |
| Arrow keys, Shift+arrow | Nudges the selection 1 px, or 10 px; keys pressed in one burst are one save and one undo step |
| Esc | Cancels a drag in progress, then clears the selection, then returns to Select, then closes the palette |
| `?` | Opens the list of every canvas shortcut |

The palette searches the icons of every pack you have downloaded (names, aliases and pack names, with one typo
tolerated), plus the node shapes, **Zone**, **Row** and **Column**. With the search box empty it groups them into
collapsible categories, each with a count and an icon on every item: **Basics** (Box, Text, Zone, Row, Column,
Note), **Zones**, **Shapes**, and one category per icon pack (packs start collapsed; the state is remembered). A search gives one
ranked list with each row tagged by its category. Packs not downloaded yet are listed under **Not downloaded** with a
**Fetch** button; nothing is fetched until you press it. **Zones** holds the generic Zone and then the provider groups, each with its real header icon and a swatch of its
outline: AWS (Cloud, Account, Region, VPC, Availability Zone, public and private subnets, Auto Scaling group,
corporate data center, Spot Fleet, server and EC2 contents), Azure (management group, subscription, resource group,
virtual network, subnet), Google Cloud (cloud, project, region, zone, VPC network, subnet) and Kubernetes (cluster,
namespace). Dropping one adds a zone with that style (`color: aws-vpc` in the YAML), and search finds them by name
("vpc", "subscription", "project"). The styles come from the active theme, so a theme can add its own; the icons need
the provider's pack (**Fetch** it from the palette). A dropped item first shows a dashed placeholder at the drop
point, and each save is patched into the diagram in place, so fonts and images do not reload. A zone cannot be dropped inside itself: the reason appears next to the pointer for three seconds. New titles and labels are written as plain YAML text unless they need quotes (a colon and space, a leading symbol, `yes`/`no`/`null`, a number, or a comma inside a one-line entry).
If the file changes on disk while you edit, the edit is dropped with "File changed on disk; edit not applied" and
the undo history is cleared.

### Elements and properties

The **Elements** button of the toolbar shows a panel on the right: the diagram as a tree (zones nested by what they
hold, rows and columns with their members, free nodes, and an **Edges** group listing `from → to (label)`), each row
with its icon. Click a row to select the element on the canvas (and highlight its YAML when the code panel is open);
selecting on the canvas highlights and reveals the row. A filter box narrows the tree. Selecting an element opens the
panel; the **pin** button keeps it open or closed as you left it, and the browser remembers that.

Under the tree the **properties** of the selection: a node has title, text, icon (**Change…** opens a search over the
downloaded packs), kind, class and position and size; a zone has label, style (the provider zone styles), class and
position and size; an edge has from and to (node dropdowns), label, route, dashed, color, class and arrow ends. Press
Enter or leave the field to apply it; a select or checkbox applies at once. Each change is one save and one undo step,
only the keys the YAML loader accepts are written, and a refused value shows as a message at the pointer. With several
elements selected the panel shows the fields they share and changes all of them in one step. Above the fields, quick
actions: **Duplicate** (a copy offset by 30 px, in the same zone and row or column), **Add connection** (Connect from
that node), **Group as a row or column**, **Ungroup**, **Move to zone** (a list of zones, or the top level), **Change
style**, and for an edge **Reverse**, **Add a parallel edge** and **Delete**.

## Open another folder

**Open folder…** in the header browses folders on this machine, with the number of specs in each, and has a
path box for pasting a path. Opening a folder makes it the workspace: its diagrams (subfolders included, shown
with their relative path, such as `kubernetes/eks_platform.py`) replace the current ones and are watched for
changes, without restarting `serve`.

Opening a folder runs its Python specs, exactly like `spinagram serve <folder>`: open only folders you trust.

The navbar switches between **Diagrams**, **Themes** and **Icon packs**; **Docs** opens this site.
The left sidebar lists the 10 diagrams you opened last (kept in your browser).

- **Diagrams page**: every diagram as a card with a live thumbnail, grouped by
  [category](/docs/write/python#catalog-metadata) (AWS, Google Cloud, Kubernetes… inferred from icons when not
  declared). Type to search ids, titles, subtitles, categories and tags (every word must match);
  click tag chips to require tags. Specs that fail to load are listed with their error.
- **Diagram view**: every spec under the paths. Saving a spec, its `_defaults.yaml`, a `.py` helper or
  any file of the theme (including the themes it `extends`) re-renders in place, keeping zoom and
  pan. Errors show over the last good render. Wheel zooms, drag pans, `f` fits, `0` is 100 %; the
  header switches the layout engine for diagrams with `layout:`. Overflow, icon warnings and
  not-downloaded icon packs are flagged.
- **Styles**: **Inspect** (or `i`) opens the CSS inspector: click an element to see its classes,
  computed style and the rules behind it. Saving any stylesheet a diagram uses, wherever it lives,
  re-renders that diagram. See [CSS by backend](/docs/customize/css-reference#live-inspector-and-live-reload).
- **Themes page**: a card per theme (built-in, then your custom theme) showing a sample diagram rendered
  in that theme, with a search box. Open a card for the full token sheet.
- **Icon packs page**: a card per pack (downloaded first) with twelve sample icons, with a search box.
  Open a card for the full grid and **Fetch**.
- **Themes**: token sheet of the built-in and active theme: colours (with the token they point to),
  font roles rendered in the embedded fonts, node and zone styles with previews, defaults and chrome.
- **Icon packs**: registry state, a searchable grid per downloaded pack and **Fetch** for missing
  ones. `serve` never downloads during a render (a missing pack is flagged with a link to fetch it).

## Security

The server binds 127.0.0.1 only and rejects other `Host` headers. Reading sources, saving and browsing folders
need a header the UI sends (`X-Spinagram: 1`); the server sends no CORS headers, so a page on another site
cannot send it and cannot read or write your files. Saves go only to files the panel lists for a loaded
diagram, are refused when the file changed since it was read, keep the file's line endings, and replace the
file atomically, so a crash never leaves it half written.
