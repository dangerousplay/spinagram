title: YAML specs
description: The same diagrams as data files, for generated or non-Python workflows.
---

Every Python feature has a YAML form. YAML suits diagrams generated by other tools, or teams that
prefer data files; Python is easier for anything with repetition. Both load into the same model and
render identically.

<include meta='title="examples/quickstart.yaml"'>../../../examples/quickstart.yaml</include>

```bash
spinagram render examples/quickstart.yaml -f svg,png,pptx -o out/
```

## Structure

| Key | Meaning |
|---|---|
| `id`, `title` | Required. The id names files and orders slides |
| `subtitle`, `source`, `kicker` | Page chrome text |
| `layout` | Engine and direction for automatic layout: `{engine: elk, direction: down}` |
| `groups` | Nested containers: `{id, label, style, direction, children: [...]}` |
| `nodes` | `{id, title, text, icon, style, kind, x, y, w, h}`; `at: [x, y, w, h]` is a shorthand |
| `edges` | Shorthand strings or `{from, to, label, color, dashed, via, arrow}` |
| `zones`, `tables`, `legend` | Fixed-position extras, see [Manual layout](./manual-layout.mdx) |
| `facts`, `locale` | [Facts](./facts.mdx) file and number format |

## Edge shorthand

`"<from> -> <to>[: label]"`, where an endpoint is a node id (the facing side is picked
automatically) or `node.side[@frac]` with `side` one of `top|bottom|left|right|center` and `frac` a
position from 0 to 1 along that side. `<-`, `<->` and `--` (no arrow) work too.

## Folder defaults

A `_defaults.yaml` next to the specs supplies keys every diagram in that folder shares, such as
`facts`, `locale` or `layout`. Files starting with `_` are not loaded as diagrams.

## From Python to YAML

`spinagram layout spec.py -o spec.yaml` writes any diagram, Python or YAML, as an explicit YAML spec
with its computed positions.
