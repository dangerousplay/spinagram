Adding an icon is one argument. No downloads to manage, no imports, no paths to configure:

```python
d.box("Orders DB", icon="aws:rds")
d.box("Cluster", icon="gcp:gke")
d.box("Router", icon="network:router")
d.box("Our portal", icon="assets/acme.svg")     # any SVG or PNG, relative to the spec
```

The first time a diagram uses a pack, spinagram downloads it into `~/.cache/spinagram/icons`. After that it
works offline.

## Find the name you need

```bash
spinagram icons search "load balancer"
```

```text
aws:elastic-load-balancing-application-load-balancer
aws:elastic-load-balancing-network-load-balancer
azure:load-balancers
…
```

Short aliases work wherever they exist: `aws:s3`, `aws:alb`, `aws:ec2`, `gcp:gke`, `azure:aks`, `network:fw`,
`selfhosted:pve`. You can also browse every pack visually in `spinagram serve` under **Icon packs**.

## Icons that adapt

- **Dark fills.** Where a pack has light artwork for an icon, spinagram uses it automatically on dark boxes.
- **Legends.** `d.add_legend({"aws:sqs": "Async messaging"})` uses the icon itself as the swatch.
- **Categories.** A diagram full of `aws:` icons is tagged `aws` and filed under **AWS** in the catalog, with no
  metadata to write.
- **Everywhere.** Icons stay vectors in SVG, PowerPoint and Figma.

## Bring your own

A single file is just a path. For a whole set (your company's product icons, say), register a folder, an npm
package or a GitHub repository as a pack and reference it like the built-in ones:

```bash
spinagram icons add acme --dir ./brand/icons          # then icon="acme:portal"
spinagram icons add acme --github acme/brand-icons   # or --npm, --zip
```

Details, aliases and the full pack list: [Icon packs](/docs/customize/icons).
